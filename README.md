# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности — **товар** и **покупатель**. Для описания данных, которыми обменивается приложение (модели, слой коммуникации, представление), в файле `src/types/index.ts` объявлены интерфейсы и типы.

### Интерфейс `IProduct`

Описывает товар, который отображается в каталоге и может быть добавлен в корзину.

```ts
interface IProduct {
  id: string; // уникальный идентификатор товара
  description: string; // текстовое описание товара
  image: string; // имя файла изображения (склеивается с CDN_URL)
  title: string; // название товара
  category: string; // категория товара (софт-скил, хард-скил и т. д.)
  price: number | null; // цена в синапсах; null означает, что товар недоступен
}
```

### Интерфейс `IBuyer`

Описывает данные покупателя, которые тот вводит при оформлении заказа.

```ts
type TPayment = "card" | "cash";

interface IBuyer {
  payment: TPayment | ""; // выбранный способ оплаты; пустая строка — не выбран
  email: string; // электронная почта покупателя
  phone: string; // телефон покупателя
  address: string; // адрес доставки
}
```

### Типы для обмена с сервером

- `IProductsResponse` — ответ сервера на запрос каталога товаров:

```ts
interface IProductsResponse {
  total: number; // общее количество товаров
  items: IProduct[]; // массив товаров
}
```

- `IOrderPayload` — данные заказа, которые отправляются на сервер при оформлении покупки. Интерфейс **расширяет** `IBuyer`: все поля покупателя (`payment`, `email`, `phone`, `address`) наследуются, дублирования нет, а специфичные для заказа поля описываются дополнительно:

```ts
interface IOrderPayload extends IBuyer {
  total: number; // итоговая стоимость заказа
  items: string[]; // массив id товаров, входящих в заказ
}
```

- `IOrderResponse` — ответ сервера на оформление заказа:

```ts
interface IOrderResponse {
  id: string; // идентификатор заказа
  total: number; // итоговая сумма заказа
}
```

- `BuyerErrors` — тип для объекта с сообщениями об ошибках валидации полей покупателя. Выведен из ключей `IBuyer`, поэтому при изменении набора полей `IBuyer` автоматически подстраивается. Если поле валидно, соответствующего свойства в объекте нет:

```ts
type BuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

## Модели данных

Модели данных отвечают **только за хранение и работу с данными**. Они не работают с DOM, не знают о вёрстке и не зависят от слоя коммуникации. Каждая модель решает ровно одну задачу, что обеспечивает изолированность и масштабируемость архитектуры.

Все модели расположены в папке `src/components/models/`.

### Класс `Products` — каталог товаров

Файл: `src/components/models/Products.ts`.

**Назначение:** хранение массива всех товаров и товара, выбранного для подробного отображения.

**Конструктор:** собственного конструктора нет — используется конструктор по умолчанию.

**Поля:**

- `private items: IProduct[]` — массив всех товаров каталога. По умолчанию пустой. Хранит полный список товаров, полученный с сервера.
- `private preview: IProduct | null` — товар, выбранный пользователем для подробного отображения в модальном окне. По умолчанию `null`.

**Методы:**

- `setItems(items: IProduct[]): void` — сохраняет переданный массив товаров в модель. Принимает массив товаров. Ничего не возвращает.
- `getItems(): IProduct[]` — возвращает массив всех товаров каталога.
- `getItem(id: string): IProduct | undefined` — находит и возвращает товар по его `id`. Если товар не найден, возвращает `undefined`.
- `setPreview(item: IProduct): void` — сохраняет товар, выбранный для подробного отображения. Принимает товар.
- `getPreview(): IProduct | null` — возвращает товар, выбранный для подробного отображения, либо `null`, если товар не выбран.

### Класс `Basket` — корзина

Файл: `src/components/models/Basket.ts`.

**Назначение:** хранение товаров, выбранных покупателем для покупки.

**Конструктор:** собственного конструктора нет.

**Поля:**

- `private items: IProduct[]` — массив товаров, находящихся в корзине. По умолчанию пустой.

**Методы:**

- `getItems(): IProduct[]` — возвращает массив товаров в корзине.
- `addItem(item: IProduct): void` — добавляет товар, полученный в параметре, в массив корзины.
- `removeItem(item: IProduct): void` — удаляет товар, полученный в параметре, из массива корзины (по `id`).
- `clear(): void` — очищает корзину.
- `getTotalPrice(): number` — возвращает суммарную стоимость всех товаров в корзине (товары с `price === null` считаются как 0).
- `getCount(): number` — возвращает количество товаров в корзине.
- `hasItem(id: string): boolean` — проверяет наличие товара в корзине по `id`. Возвращает `true`, если товар есть, иначе `false`.

### Класс `Buyer` — данные покупателя

Файл: `src/components/models/Buyer.ts`.

**Назначение:** хранение и валидация данных покупателя, вводимых при оформлении заказа.

**Конструктор:** собственного конструктора нет. Начальное состояние полей — пустые строки.

**Поля:**

- `private data: IBuyer` — объект с данными покупателя: способ оплаты (`payment`), адрес (`address`), телефон (`phone`), электронная почта (`email`).

**Методы:**

- `setData(data: Partial<IBuyer>): void` — сохраняет переданные данные в модель. Принимает частичный объект `IBuyer`: можно передать только одно поле, при этом остальные значения сохраняются (реализовано через слияние объекта).
- `getData(): IBuyer` — возвращает все данные покупателя (копию объекта).
- `clear(): void` — очищает данные покупателя, сбрасывая все поля в пустые строки.
- `validate(): BuyerErrors` — валидирует данные покупателя. Возвращает объект типа `BuyerErrors`, в котором присутствуют свойства только для невалидных полей с текстом ошибки. Правила валидации: поле валидно, если оно не пустое; для `payment` — если выбран вид оплаты (`'card'` или `'cash'`).

## Слой коммуникации

Отвечает за обмен данными между приложением и сервером. Не работает с моделями напрямую — получает и возвращает данные, а сохраняет их в модели тот, кто вызывает методы класса (в текущей версии — `main.ts`, позже — презентер).

Класс расположен в `src/components/сommunication/AppApi.ts` и использует **композицию**: принимает в конструктор объект, соответствующий интерфейсу `IApi` (базовый класс `Api` из `src/components/base/Api.ts`).

### Класс `AppApi`

**Назначение:** выполнение запросов к серверу «Веб-ларёк» для получения каталога товаров и отправки заказа.

**Конструктор:** `constructor(api: IApi)` — принимает экземпляр, реализующий интерфейс `IApi` (методы `get` и `post`). Используется композиция, а не наследование, чтобы класс не зависел от конкретной реализации транспорта.

**Поля:** собственных полей нет, кроме приватного поля `api: IApi`, хранящего переданный в конструктор объект.

**Методы:**

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, содержащим массив товаров и их общее количество.
- `createOrder(data: IOrderPayload): Promise<IOrderResponse>` — выполняет POST-запрос на эндпоинт `/order/`, передавая данные заказа (способ оплаты, контакты, адрес, сумму и массив `id` товаров). Возвращает промис с объектом, подтверждающим покупку (идентификатор заказа и итоговая сумма).

### Взаимодействие слоёв

1. `main.ts` создаёт экземпляр `Api` с базовым URL из `constants.ts`.
2. `main.ts` создаёт экземпляр `AppApi`, передавая ему `Api`.
3. `AppApi.getProducts()` запрашивает каталог, `main.ts` сохраняет массив в модель `Products` и выводит его в консоль.
4. Позже презентер будет вызывать `AppApi.createOrder()` при оформлении заказа, передавая данные из моделей `Basket` и `Buyer`.

Такое разделение соответствует принципу единственной ответственности: `Api` отвечает за HTTP-транспорт, `AppApi` — за конкретные эндпоинты, модели — за данные, а `main.ts` (в будущем — презентер) — за связывание слоёв.
